FluxHelper 3.1.0 — рефакторинг безпеки й продуктивності
=========================================================

ПК — ZERO-DISK ARCHITECTURE (ГОВІРНЕ)
-------------------------------------
Файли інтерфейсу БІЛЬШЕ НІКОЛИ не пишуться на диск:
  * видалено WriteUiFiles/UiDir — папка %APPDATA%\FluxHelper\UI\
    більше не створюється (зачищається автоматично після оновлення
    з 3.0.0, разом із залишками ui.html/ui.css/ui.js від 2.9.2);
  * увесь фронтенд (index/ui.css/ui.js/appdata.js) віддається СТРОГО
    З ОПЕРАТИВНОЇ ПАМ'ЯТІ через віртуальний хост
    https://app.fluxhelper/ (WebResourceRequested);
  * фільтр AddWebResourceRequestedFilter тепер реєструється ЯВНО —
    подія гарантовано приходить у будь-якому рантаймі WebView2;
  * аварійний фолбек перероблений: замість NavigateToString (голий
    HTML без стилів) — повторна навігація на віртуальний хост;
  * навігації file:// у вікні заборонені — на диску немає жодного
    HTML і з'являтись йому звідки.

SQL FIREWALL (ПК + Android)
----------------------------
Усі SQL-запити з інтерфейсу до Cloudflare D1 проходять жорсткий
фільтр ДО мережі (у main.cpp та Cloud.java — дзеркальна логіка):
  * заборонені назавжди: DROP / ALTER / ATTACH / DETACH / PRAGMA /
    VACUUM / REINDEX / REPLACE / GRANT / REVOKE / load_extension;
  * заборонено ВИДАЛЕННЯ рядків таблиці users з клієнта (аккаунти
    видаляються лише вручну в Cloudflare);
  * заборонено запис колонки role (роль призначається серверно);
  * CREATE дозволений лише для bootstrap-таблиць users/device
    (IF NOT EXISTS);
  * лише один стейтмент на запит, довжина <= 6000 символів;
  * ключові слова не сховати у рядкових літералах, коментарях
    (-- і /* */) або через \t-екранування у JSON.
Заблокований запит не витрачає токен: клієнт одразу отримує 403.
Токен D1 як і раніше живе лише в нативному коді (XOR+base64).

CSS — ВИПРАВЛЕНІ НЕЗАКРИТІ КОМЕНТАРІ (головний фікс цього релізу)
------------------------------------------------------------------
У ui.css було 3 (ПК — 2) коментарі без закриття «*/»: кожен із них
«з'їдав» усі правила нижче — саме тому ламалися стилі ПРОФІЛЮ і
СВІТЛОЇ ТЕМИ. Всі відновлені, баланс перевірено автоматично.

УСІ 7 ТЕМ ПОВЕРНЕНІ
--------------------
Океан / Захід / Ліс / Аврора знову у виборі (стандартна, світла,
Liquid Glass + 4 нові-старі): плитки відновлені в налаштуваннях,
THEME_LIST розширено, синхронізація теми між ПК і телефоном
працює для всіх семи. Тема відображається одразу — навіть без мережі.

LIQUID GLASS БЕЗ ЛАГІВ
-----------------------
  * під час активного скролу блюри тимчасово гаснуться
    (клас glass-scroll, 160 мс після зупинки) — кадр дешевший,
    скрол плавний навіть на слабких машинах;
  * важкі blur(16-18px) знижені до 12px — вигляд той самий;
  * lite-glass (аварійний режим для слабких GPU) тепер має
    повноцінні стилі без блюрів;
  * prefers-reduced-motion поважається.

МЕРЕЖА — БЕЗ СПАМУ
-------------------
  * агресивний поллінг розкладу КОЖНІ 2.5 С замінено на щадні
    30 С у зв'язці з живим SSE (EventSource) — зміни прилітають
    миттєво через SSE, а поллінг лишається страховкою;
  * предмети/вчителі: 15 с -> 30 с;
  * при поверненні на вкладку — миттєве підтягування (300 мс).

ЖИВІ ТАЙМЕРИ УРОКІВ
-------------------
На картках ЗАРАЗ і ДАЛІ з'явився зворотний відлік:
  * ЗАРАЗ · «ще 14 хв» (до кінця уроку);
  * ДАЛІ · «через 6 хв» (до початку).
Текст оновлюється ЩО ХВИЛИНУ без перебудови DOM (лише
textContent) — інтерфейс не сіпається. Повний перерендер — лише
коли урок фактично став або скінчився.

ТЕЛЕФОН — ІНШЕ
---------------
  * SQL-файрвол у Cloud.java (той самий захист, що на ПК);
  * pollSchedule 30 с + SSE — менше трафіку й розряду батареї;
  * усі 7 тем у налаштуваннях.

3.1.0 FINAL — завершення безпеки (до реліз-кандидата)
=========================================================
* CFQ COMMAND WHITELIST: сирий SQL з JS ВИДАЛЕНО як клас — клієнт шле
  лише {"cmd","args"} з закритого списку (bootstrap/device_ping/sync_push/
  settings_push/sync_flag/get_role/sync_pull/sts_get/settings_get/
  user_exists/find_email/account_merge); SQL жорстко зашитий у C++/Java
  з параметризацією '?'. Міграції схеми (CREATE/ALTER/DROP) виконує ЛИШЕ
  нативний хост при старті (D1Bootstrap) — ліковано schema-drift (beta).
* BOOT TOKEN: кожне повідомлення моста ПК несе одноразовий токен сесії
  (RandHex(16), живе в ОЗУ); сторінка, відкрита поза застосунком,
  моста не бачить.
* NATIVE ZOOM: посилання з паролями (?pwd=...) видалені з ui.js/
  ui_desktop_js.h/ui_desktop_data.h — живуть ТІЛЬКИ в XOR-обфускованих
  масивах у C++/Java; клік «Приєднатися» шле fh:zoomjoin|<предмет>|<група>
  (ПК) / AndroidHost.zoom (телефон) ПІСЛЯ перевірки входу. URL у JS
  не з'являється НІКОЛИ; у fbget-відповідях НЕ-адмінам значення link/links
  замінені на маркер "#z#". Копіювання уроку більше не містить посилання.
* STRICT TLS: видалено SECURITY_FLAG_IGNORE_* у WinHTTP та WinINet —
  MITM-сніффери (Fiddler/Charles) більше не можуть перехопити токен бази.
* Токен D1: однобайтове XOR 0x5A -> 8-байтовий ключ (C++) / 7-байтовий
  (Java); буфери витираються після формування заголовка (SecureZeroMemory).
* ГЕЙТ ЗАПИСУ RTDB: schedule/subjects/teachers відкриті лише ролі
  admin/developer, підтвердженій НАТИВНО (D1 sessions JOIN на ПК;
  приватні fh_auth prefs + кеш ролі на Android — JS роль довести не може).
  Записи додають auth=<Firebase ID token> (нативний signInWithIdp, <50 хв).
* ФІКС 3.0.0: подвійний .json у fh:fbput/fh:fbdel писав розклад у
  смітникові вузли «*.json.json» — протокол вирівняно (суфікс додає хост).
* Мережа: SSE/EventSource і прямі fetch(DB_URL) із JS видалені; читання
  лише через нативні мости (fh:fbget / AndroidHost.fbGet). Поллінг 30 с
  (видимий екран), пауза у фоні, doFetch 45 с — страховка.
* SKELETON/SHIMMER при завантаженні розкладу + анімація адмін-модалки;
  logo.png — один файл замість 4 дублікатів base64 (-500 КБ розпухання).
* Оновлення ПК: SHA-256 контрольна сума завантаженого exe (з вузла /update
  або сайдкара <файл>.sha256) + обов'язкова PE-магія MZ — битий бинарник
  не встановлюється НІКОЛИ.
* Android 14+: foregroundServiceType="specialUse" + PROPERTY_SPECIAL_USE
  (ліковано MissingForegroundServiceTypeException у LoginKeepService).
